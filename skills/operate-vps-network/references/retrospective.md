# 搭建与排障复盘

复盘日期：2026-11-11。依据既有会话、仓库脚本和部署记录整理。本轮不修改服务器现有服务；历史成功、用户报告、资料推论与本轮实验分别记录。当前状态仍以重新读取的结果为准。

## 先看结果

在一天的工作中，管理通道、Tailscale 出口、独立 REALITY 节点、HTTPS 订阅与私有采样用量已分阶段跑通。最大的可复用改进不是再增加参数，而是提前分清数据路径、用最小对照实验定位故障，并让安装器的成功条件与实际服务就绪一致。

MTU、TCP 指纹和 CDN 路径的进一步结论见[网络研究与实验](network-research.md)。那份研究不把资料结论写成已在生产验证的结果。

## 一次测试只回答一个问题

每份结果至少记录以下信息，缺失就标为未知：

- 时间和执行位置：用户电脑、手机蜂窝、VPS 本机或独立测试机。
- 客户端路径：Tailscale 出口选择、Mihomo 模式、系统代理、TUN、实际选中节点。
- 目标：具体域名/服务与协议；IPv4/IPv6、TCP/QUIC 分开。
- 证据：进程/监听、连接归属、实际 HTTP/TLS 结果、站点原始字段。
- 限制：是否经同一 VPS 回环、是否只验证语法、是否仅是用户报告。

例如，VPS 上从自己的公网地址访问自己不能验证公网入口；目标网站 HTTP 200 不能单独证明经过指定节点；WebRTC 当次只显示 VPS 不能证明所有应用和未来网络都没有旁路。

推荐顺序：

1. 读取现状，确定管理通道和正在使用的路径。
2. 离线校验候选配置，不把真实配置或凭据发往在线转换站。
3. 如确有获批变更，先准备备份与恢复，再进行最小修改。
4. 检查当前 PID、运行 UID、实际监听和 guard。
5. 用明确路径验证单用户认证，再做独立公网请求。
6. 订阅获取、规则路由、UDP/WebRTC、统计分别验收。
7. 记录完成与待办；临时资源和过期清理计时器按授权范围收尾。

本次研究只执行已允许的观察与独立实验；上述含变更的步骤是未来作业模板，不是本轮执行记录。

## 优先在服务端解决，边界明确

适合集中在 VPS 维护的内容：凭据生命周期、入口/出口防护、证书续期、订阅模板、服务启动顺序、用量采样与可用性监测。它们可减少每换一台终端都重复配置的工作。

仍需客户端参与的内容：实际使用哪条路径、哪些应用遵循系统代理、TUN 接管范围、IPv6/UDP 是否旁路、浏览器 WebRTC 行为。没有到达 VPS 的流量，VPS 不能替客户端拦截。需要终端配合时只给当前必要动作，不把全部排查工作转交用户。

## 现在不应做的优化

- 为检测网站的操作系统标签修改生产 TCP 栈、挂载 eBPF/NFQUEUE 或批量改 sysctl。
- 因某站分数提高就把 1400、1500 等单一数值推广到所有隧道。
- 在没有实际路径证据时切 DNS、加 CDN 或重装协议。
- 为采样便利开放公网管理端口，或放宽 Unix socket 父目录权限。
- 为测试方便让熟人共用 owner 凭据，或把订阅上传到第三方转换站。
- 在用户休息或独立工具不可用时反复要求切网、重跑部署或关闭唯一管理通道。

## 后续验收优先级

1. **权限与恢复：**核对 Tailscale 出口使用权与 VPS 管理访问权是否分开、现有可用备份与通知渠道。历史 member 到 exit-node 全端口授权不等于仅 owner 能管理；任何收权或演练另行安排。
2. **功能闭环：**owner 规则模式的实际命中及出口、friend 独立外网认证、双用户流量归属。
3. **持续可用：**真正证书续期及部署 hook、长期采样、重启后的管理/guard/节点/订阅/采样顺序。
4. **路径质量：**固定目标与路径的 MTU、重传、延迟和 CDN 观测。先建立基线，只有复现的功能或性能问题才进入变更实验。
5. **指纹研究：**保留原始字段和对照结果，明确改变谁建立 TCP 才能改变哪段 TCP；没有变成 Windows 或通过任意反欺诈系统的承诺。

证书正常余量、可恢复备份与独立管理通道优先于检测站评分。NAT 分类仅作为协议行为信息，不单独列为安全故障。
