# 可迁移 VPS 系统设计

## 目标与范围

- 一个仓库同时保存系统源码、部署入口、设备策略、运维 Skill 和验证。面向本人及团队同伴，不建设公开注册、计费或管理界面。
- 沿用 Ubuntu 24.04、Mihomo、现有 TCP 指纹源码、Caddy 和 systemd。Ansible 负责新主机部署。此轮只实现和离线验证，不连接或修改现有 VPS。
- 现网正在进行的 UDP/BBR 调整不自动写成最终事实；迁移前比较当前运行配置、磁盘启动配置与订阅，三者不能互相代替。

## 方案取舍

- 采用原生服务 + Ansible：适合既有 netns、tc/eBPF 与宿主防护，不引入常驻管理程序。
- Compose 仍需要宿主管理网络，反而会增加两套部署边界。NixOS/Kubernetes 会扩大迁移范围，本次不采用。
- 新增配置编译器仅负责输入校验与离线生成，使用 Python 标准库，避免再做一套远程执行系统。

## 配置来源与密钥

- `system/examples/site.json` 描述主机、监听、设备、TCP 模板、UDP 策略、订阅与 BBR。文件中只有保留地址和示例域名。
- 密钥由仓库外的 0600 JSON 输入，或由 Ansible Vault 解密到受限临时目录后输入。输入、生成目录和备份均不能放入 Git。
- 一个设备有稳定 ID，三协议分别认证并映射至同一设备 ID。凭据不复用；订阅和服务端由相同输入生成。
- 输出含凭据，只写到新建 0700 目录，文件 0600；清单记录目标权限，部署时再赋给服务读取身份。

## 协议和出口

- VLESS/REALITY 默认启用。Hysteria2 与 AnyTLS 为显式可选组件，生成器实现支持不代表现网已部署或验收。
- 设备 `tcp_profile` 可选 native/windows/ios。Windows/iOS 复用已交付双 namespace 和 SYN options 重排源码；不增加每协议一套出口。
- `udp_policy` 仅允许 deny/direct：deny 显式拒绝；direct 明确走前端受限原生 UDP 出口，不经过 TCP 指纹后端。尚未验证的 SOCKS UDP 不冒充可用功能。
- 不设置带 DIRECT 的后端故障回退。IPv6 默认拒绝。私网、元数据、Tailscale、VPS 自身地址由应用规则和内核防护共同隔离。
- owner 管理例外是客户端精确 IPv4 + TCP + SSH 端口规则，由设备字段显式控制；不能因此放宽服务端访问本机。

## 部署和生命周期

- 只针对新 Ubuntu 主机自动部署。已有服务或未知同名资源立即停止，现网收拢须先完成清单导入与差异审核。
- 生成目录 → 验证 → Ansible 明确 apply → network → 后端 → guard → 前端；订阅、证书与近似采样分开管理。
- namespace、veth、tc 与 nft 表采用专用名称；记录创建对象身份，清理前核对。禁止 flush ruleset，不修改 UFW/Tailscale 规则；存在转发过滤器时先停止由人工审核，而不是假设 accept 可覆盖其他链 drop。
- BBR 分宿主和 namespace 配置，均显式启用；不覆盖现有 tc/qdisc，不能把 Linux TCP BBR 当作 HY2 QUIC BBR。
- 证书继续外部 DNS-01 签发，由受限文件导入。仓库提供受控证书导入和检查，不包含 DNS 密钥、不自动创建 DNS API 权限。自动续期与证书更新钩子仍沿用旧独立流程，统一接入待后续验收。

## 验证与完成边界

- 离线测试覆盖输入拒绝、权限、所有协议配置、身份映射、UDP 拒绝/显式直出、秘密隔离、订阅管理例外和资源所有权。
- 使用已有官方固定 Mihomo 二进制解析合成配置；BPF C 测试复用原源码测试。
- Ansible 语法、生成文件语法、秘密扫描和文档链接检查属于本地验证。
- 干净 VPS 部署、二次运行、整机重启、真实 UDP、外网指纹、续期和迁移切换仍需另外授权测试。不能用离线通过代替“完整迁移已验收”。
